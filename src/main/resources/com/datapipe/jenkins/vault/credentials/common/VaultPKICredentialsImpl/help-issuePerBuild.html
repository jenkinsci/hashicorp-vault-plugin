By default, the issued certificate is cached and shared by all builds that use this credential. It is renewed once half of its TTL has passed, so every build receives a certificate with at least half of the TTL remaining.

When checked, every build requests its own certificate from Vault. Each build then gets the full TTL, and no private key is shared with other builds, which limits the impact of a leaked key to a single build and makes every issued certificate traceable to one build. This causes one Vault request per build.

Recommended when the credential is used by builds of different trust levels or when builds may run longer than half of the TTL.
